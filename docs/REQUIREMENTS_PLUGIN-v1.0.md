## 0. 修订说明

### 0.1 已确认的决策

| # | 决策 | 结论 | 带来的影响 |
|---|---|---|---|
| P-1 | 产品形态 | **DSH 插件**（Cordis Service + 客户端注入），不启动独立服务 | 无 HTTP 服务、无监听端口、无前端路由、无口令 |
| P-2 | 使用对象 | **自己用**，单用户 | 宿主即单用户；无账号、无隔离、无分享 |
| P-3 | 界面载体 | **独立视图（槽位注册）+ 会话内卡片 + 插件设置页** 三处 | 页面从 10 个路由降为 1 个独立视图（4 个二级页）+ 卡片 + 设置组；无 URL |
| P-4 | 存储 | 插件数据目录：结构单快照 `radar.json` + 正文分片 `texts/<id>.gz` | 原子写 + 单写者；不引入 SQLite 与原生依赖 |
| P-5 | 正文留存与重算 | **保留**（web D-5 / D-3 不变） | 规则演进可原地重算，不必重抓 |
| P-6 | 正文出口 | **默认不进模型上下文**；正文只能落盘导出；`textReadEnabled` 默认 false | 上下文预算与隐私同时解决，但多一个开关 |
| P-7 | 检索来源 | **插件自带** OpenAlex / Crossref / arXiv 直连（含出站白名单、限速、熔断） | 与 v0.2「复用宿主 `paper_search`」相反；换来结构自持、失败语义自持 |
| P-8 | 写权限 | **能力开关 + 用户审批**：删除 / 导入 / 清空 / 覆盖式重算必须先审批 | 复用宿主 `writeEnabled` + user-approval 模式，不自建鉴权 |
| P-9 | 失败语义 | **typed error + 稳定错误码**；工具永不抛栈、永不回显正文 | 错误可被模型与面板分别路由 |

### 0.3 相对 v0.2 插件的变化

v0.2 已经是插件，但只有「Agent 三件套工具」，没有界面承载，也没有正文留存。本版：

1. **补界面**：以独立视图承载排行 / 论文 / 算法详情 / 口径，下钻升为 P0。
2. **补正文留存与重算**（web D-5）：v0.2 不存正文，词典升级后无法重算。
3. **检索改为自带**（P-7），不再依赖宿主是否装了 `paper_search`。
4. **存储从单快照升级为「快照 + 正文分片 + 原子写 + 撤销墓碑」**，仍不引入数据库。
5. **工具从 3 个扩到 20 个**（读 10 / 写 10），按读 / 写分组，写操作全部受能力开关与审批约束。
6. **新增 `/radar` 命令**，只做控制面（状态 / 重算 / 导出），不做第二套 CLI。

## 1. 背景与问题

读文献有一个断层：**论文读了很多，但说不清自己到底在读什么。**

1. **算法画像缺失**：知道最近在看 Transformer 系的工作，但说不清哪些模型是真被当创新点、哪些只是基线。
2. **领域分布不可见**：跨 NLP、时序、图学习地读，没有量化各领域的投入比例。
3. **时间线无法回溯**：「我是什么时候开始关注扩散模型的」，只能翻收藏夹。
4. **登记成本高**：手工维护 Excel / 笔记，一篇篇录，坚持不下去。

现有工具都不解决这个组合：文献管理器（Zotero）管**论文**不管**方法**；笔记工具管**想法**不管**统计**；LLM 对话能临时总结一篇，但不积累、不可比、不可回看。

**为什么做成 DSH 插件而不是网站**：

- 对话就是最自然的登记入口——「把这篇加进雷达」比打开一个网页粘贴三次更省事。
- 抽取结果要能被模型接着用（「我读的论文里哪些在当基线」「帮我按算法筛出这 5 篇」），插件内天生共享上下文。
- 不用部署、不用开端口、不用记口令；数据和宿主的其它数据在一起。
- 代价：没有独立 URL、没有大面积图表空间、受宿主 UI 约束——这是本版必须接受的取舍（见 §5.2）。

## 2. 产品定位

> 一个本地优先、持久、可审计的**个人算法阅读画像库**，寄生在 DSH 宿主里：把每篇读过的论文转成「算法 × 领域 × 时间」的结构化记录，并给出排行、趋势与领域分布。

**一句话价值**：从「我读过这些论文」升级到「我在读什么、读到什么程度」。

### 2.1 成功标准（可度量）

| 指标 | 目标 | 验证方式 |
|---|---|---|
| 首次价值时间 | 装好插件到右侧栏看到第一份排行 ≤ 3 分钟 | 自测计时 |
| 单篇登记耗时（会话内） | 一句话 → 工具返回 ≤ 15 秒 | 脚本计时 |
| 单篇登记耗时（面板） | 粘贴链接到命中结果 ≤ 15 秒，人工点击 ≤ 3 | 点击计数 |
| 登记 50 篇后的排行可用性 | Top 10 中 ≥ 7 个符合直觉（≥70%） | 人工抽查（§12.3 D1） |
| 抽取可复现性 | 同一正文、同一词典版本，两次抽取逐字节一致 | golden G12 |
| 重算等价性 | 存库后重算 == 直接抽取 | golden G13 |
| 上下文成本 | 单次工具返回 ≤ 12,000 字符；正文泄漏为 0 | 契约测试 |
| 单篇扫描性能 | 40 万 code point ≤ 300ms | 基准测试 |
| 加载副作用 | 插件加载到激活期间零网络、零写盘 | 加载期网络与 fs 断言 |

### 2.2 非目标（本期明确不做）

- 不做文献管理器替代品（不管理 PDF 原件、不做笔记、不接管 Zotero）
- 不做论文阅读器 / 翻译器
- 不做引文网络分析（snowballing）
- **不做多用户、账号、团队协作、分享链接**
- **不做独立 URL / 深链接**——插件没有自己的地址
- **不把正文喂给模型**（P-6），除非显式开启 `textReadEnabled` 且用户当次要求
- **不做正文全文检索（FTS）**——存正文 ≠ 要搜正文
- **不持久化 PDF 原件与上传文件**
- 不追求「算法名识别率 100%」——准确性靠词典人工治理
- **不自建 HTTP 服务、不自建前端路由、不自建鉴权**

## 3. 用户与场景

**唯一用户**：维护自己阅读轨迹的研究者本人（即 DSH 宿主的使用者）。

| 场景 | 触发 | 期望结果 |
|---|---|---|
| S1 领域入门 | 想进一个新方向（如「空气质量预测」） | 会话里说「搜一下这个领域」，候选卡片可勾选批量登记 5–10 篇 |
| S2 日常精读 | 读完一篇论文 | 说「加进雷达」+ 链接 / 附件；或面板粘贴链接；或粘贴正文 |
| S3 复盘 | 月末 / 开题前 | 面板看排行、年份跨度；或问「我最近在读什么」 |
| S4 组会汇报 | 需要说明「我读了什么」 | 说「导出成 CSV」→ 落盘到工作区 |
| S5 程序化接入 | 想用脚本批量操作 | 直接调用同名工具（宿主 API 与面板无第二套实现） |
| S6 迁移与备份 | 换电脑、担心丢数据 | 导出 → 导入；含 v0.2 `store.json` 迁移 |
| S7 词典升级 | 新增了一批算法名 | `/radar reextract --dry-run` 预览 → 确认 → 全量重算 |
| S8 追问 | 「这几篇里 Transformer 是怎么用的」 | 工具回结构化命中 + 证据片段，模型据此作答 |

## 4. 术语定义

| 术语 | 定义 |
|---|---|
| **算法条目** | 词典中的一条记录，含规范名、类型、分类、别名集合 |
| **别名** | 同一算法的不同写法（`SVM` / `support vector machine` / `支持向量机`） |
| **提及（mention）** | 一篇论文中命中某算法的记录；以「论文 × 算法」为一条，含次数 |
| **论文数（papers）** | 提及该算法的**不同论文**数量，默认排行口径 |
| **提及数（mentions）** | 该算法在所有论文中的**总出现次数** |
| **全文级 / 摘要级** | 统计所依据的正文来源：全文，或仅摘要（计数偏低） |
| **领域（field）** | 论文的多标签归属 |
| **词典版本（dictVersion）** | 抽取时所用词典的版本号，写入每条提及 |
| **论文键（paperKey）** | 去重用的三种键：`doi:` / `arxiv:` / `title:` |
| **正文留存（retained text）** | 规范化后存入 `texts/` 的正文（gzip），不进上下文、只用于重算与完整导出 |
| **重算（reextract）** | 用当前词典对已留存正文重新抽取，替换该论文全部提及 |
| **陈旧（stale）** | 论文的提及字典版本 ≠ 当前词典版本，可一键重算 |
| **示例数据（isSample）** | 引导用的假数据，默认不计入任何统计 |
| **能力开关（writeEnabled）** | 插件配置里的总闸；关闭时所有写工具不注册 |
| **工具（tool）** | 模型面向的函数，`defineTool` 声明，纯 JSON 进 / 出 |
| **独立视图（view）** | 经 `ctx.slots.register('conversation.view', …)` 挂到宿主视图条上的一个整宽页面，人面向。下文简称「面板」 |
| **槽位（slot）** | 宿主开放的注册点（如 `conversation.view`）；插件只能往槽位注册，不能直接改宿主 DOM |
| **remote 通道** | 客户端经 `ctx.remote.<ns>.<method>` 调宿主 Service 方法；与模型工具落在同一层 |
| **会话卡片（card）** | 工具调用结果在对话里渲染成的紧凑视图 |
| **上下文预算** | 单次工具返回允许占用的字符上限 |

## 5. 范围

### 5.1 In scope

1. 论文登记：会话内链接 / DOI、粘贴正文、PDF 附件、领域检索批量登记
2. 算法词典抽取与计数（参考文献剔除、章节归属、证据片段、词典版本）
3. 排行（论文数 / 提及数双口径）、类型筛选、搜索、算法下钻
4. 时间维度（首见 / 最近年份、趋势）
5. 领域维度（多标签、占比、领域 × 算法矩阵）
6. 数据管理：删除（可撤销）、导出、导入（兼容 v0.2）
7. 正文留存与原地重算
8. 独立视图四页、会话卡片、插件设置组、`/radar` 命令
9. 空状态引导与示例数据
10. 安装 / 卸载 / 版本兼容

### 5.2 Out of scope（本期，且**由插件形态决定**）

| 不做 | 原因 |
|---|---|
| 独立 URL、书签、分享链接 | 插件无自有地址 |
| 自由布局、浮动面板、多栏拖拽、自定义窗口尺寸 | 视图由宿主托管，尺寸由内容区决定 |
| 大面积可视化画布（自由坐标系、缩放平移） | 视图是列表型界面，不是图表工作台 |
| 自建调色板、自定义主题 | 必须跟随宿主 token（FR-9.3） |
| 常驻后台任务、定时抓取 | 宿主插件加载期必须零副作用（FR-10.5） |
| 多用户 / 权限分级 | 宿主单用户 |
| 账号、口令、Token 校验 | 无网口 |
| 浏览器内正文渲染 | P-6 |
| 正文全文检索 | 存正文 ≠ 要搜正文 |

## 6. 界面表面与信息架构

插件没有路由，只有**表面（surface）**。宿主给客户端一个 `slots` 服务，插件用 `ctx.slots.register()` 往具名槽位注册视图。

**已在本机实测确认**（2026-10-22，`spike/radar-spike` v2，Chromium 1440×900，浅色 + 深色）：

| 槽位 | 描述符 | 渲染结果 | 是否适合本项目 |
|---|---|---|---|
| **`main`** | `{ name:'main', key:'<id>' }` + Component | **主内容区整宽页面**，铺满右侧区域 | ✅ **主视图用它** |
| **`sidebar.panellist`** | `{ name:'sidebar.panellist', id, order, label:()=>string }` + IconComponent | 侧栏一行，渲染成 `<button aria-label="<label>">`（class 含 `panelRow`），点击切到对应 `main` 视图 | ✅ **入口用它** |
| `conversation.view` | `{ name:'conversation.view', id, order, label }` + Component | 会话内的标签页，**必须先开会话才可见**（落地页上不渲染） | ❌ 用于迷你侧面板时才用 |

三个槽位同时注册全部成功（`slot report: [{"slot":"main","ok":true},{"slot":"sidebar.panellist","ok":true},{"slot":"conversation.view","ok":true}]`），证明确实存在「插件新增独立视图」这条路；**但「独立页面」的正确组合是 `sidebar.panellist` + `main`，不是 `conversation.view`**——后者只在会话内部出现，落地页看不到。

> 纠正记录：本文件上一版把 `conversation.view` 当成了独立视图的入口，依据是 `dsh-zotero` 的用法。v0.2 的 `dsh-plugin-paper-algo-radar` 与实测都表明，那只是「会话内一个标签」。一个整页面的雷达必须挂 `sidebar.panellist` + `main`。

| 表面 | 挂载方式 | 主要内容 | 版本 |
|---|---|---|---|
| **S-a 视图·排行**（默认页） | `main`（`key:'radar'`）+ `sidebar.panellist`（`id:'radar'`, `order`） | 统计串、排行表、类型筛选、搜索、覆盖率条、旧口径标记 | W0 |

**注册形态**（这是 `spike/radar-spike/lib/client.js` 里跑通过的代码，不是伪代码）：

```js
const inject = ['slots'];                       // 客户端插件声明依赖 slots 服务

function apply(ctx) {
  // 1) 主内容区：一个整宽独立页面
  const dMain = ctx.slots.inject('main', () =>
    ctx.slots.register({ name: 'main', key: 'radar' }, RadarWorkspace));

  // 2) 侧栏入口：与 main 配对，label() 会成为该按钮的 aria-label
  const dPanel = ctx.slots.inject('sidebar.panellist', () =>
    ctx.slots.register(
      { name: 'sidebar.panellist', id: 'radar', order: 65, label: () => '算法雷达' },
      RadarIcon));

  // 3) 卸载：把 disposer 交回去，视图条上不留空壳
  return () => { dMain(); dPanel(); };
}
```

**已验证的契约细节**（照抄即可，别再猜）：

- `dsh.client.inject` 只需 `["@deepseek-ai/dsh-client-ui-slots"]`；少列会拿不到 `ctx.slots`。
- 描述符**不需要** `registrant`、`locale`、`outputSchema`；`label` 返回字面量字符串可行，不必走 `t()`。
- `main` 用 `key`，`sidebar.panellist` 用 `id`，两者取同值即配对。
- `order` 决定侧栏顺序（实测 `order:65` 落在「插件 / 自动化任务」之后）。
- 宿主把客户端模块编进启动清单：`plugins/??<包名>/client.js&rev=<内容哈希>`；`.dsh.client.inject` 会原样出现在该清单条目里。
- **改客户端文件后 `rev` 变化，旧 URL 直接 404 ⇒ 必须重启宿主**；隔离实例上没有观察到热重组生效。

**面板取数通道（已实测，推荐）**：宿主侧注册 exact 路由，客户端同源 `fetch`。

```js
// 宿主（lib/index.js）
ctx.inject(['webServer'], (webCtx) => {
  for (const endpoint of ['state', 'scan', 'search', 'register-one', 'remove', 'export']) {
    webCtx.effect(() => webCtx.webServer.register({
      kind: 'exact',
      path: `/paper-algo-radar/${endpoint}`,
      handler,
    }));
  }
});

// 客户端
const res = await fetch('/paper-algo-radar/state', { cache: 'no-store' });
```

比 `ctx.remote`（typert 契约）简单一大截，v0.2 与 `dsh-paper-algo-radar` 都跑通了。代价：路由是**同源 HTTP**，需要宿主有 `webServer` 服务（桌面端与 web 端都有）。

**已用真实数据验证**（`spike/evidence/radar-w0-light.png`）：5 篇论文 / 13 个算法 / 124 次提及，排行 CNN 2 篇 45 次、SVM 2/4、LSTM 1/59，覆盖率条 40% / 20%，深浅色都跟随。

**表面规则**（硬约束）：

1. 视图里每一次操作，都必须落到与模型工具**同一个服务方法**，禁止第二套实现（继承 web FR-8.1 的精神）。取数通道两条都行：`webServer` 的 exact 路由（v0.2 已验，见下）或 `ctx.remote`；选一条，不要混。
2. 卡片只渲染工具已经返回的结构化结果，不二次请求、不二次计算。
3. 视图不渲染正文（P-6）；证据片段是唯一允许出现的原文，且 ≤ 200 code point / 条。
4. 样式只用宿主 token：**实测可用**——`--dsw-alias-bg-layer-1/2`、`--dsw-alias-label-primary/secondary`、`--dsw-alias-border-l2`、`--dsw-alias-state-business-primary`、`--dsw-alias-interactive-bg-hover`、`--dsw-radius-sm`，七个在浅色与深色下都解析出颜色。**不出现任何颜色字面量**。
5. 视图注册返回 disposer，必须挂到 `ctx.effect` 或 `apply` 的返回值上；卸载后视图条上不得留空入口。

## 8. 统计口径（核心规则，任何实现不得偏离）

> 本节是抽取引擎的唯一行为规范。R1–R11 与 v0.4-web §8 **逐条相同**（统计口径与承载形态无关），此处只压缩重述并标注插件版新增的 R12。若两版出现措辞冲突，以本节为准并回头修 web 版。

> **实现状态（2026-10-22）**：R1–R8 已在 `paper-algo-radar/lib/extract.js` 实现为**纯函数**（零 IO、零配置），60 条规则级测试通过。**但 §12.1 的 A1 / A2 / A3 依赖 v0.2 的样例正文，尚未验证——不要据此认为抽取已通过验收。**

### 8.0 总则

- **G-1** 抽取引擎是**纯函数**：`extract(text, dict, dictVersion) → result`。不读时钟、不读环境、不发网络、不碰数据库、不读插件配置。
- **G-2** 同 `(text, dict, dictVersion)` 任意两次调用，输出 JSON 逐字节一致；键顺序固定，集合一律数组。
- **G-3** 处理顺序固定 R1 → R8，**顺序本身是规范的一部分**。
- **G-4** 所有长度与偏移按 **code point** 计。
- **G-5** 禁用 `localeCompare` / `Intl.*` / `toLocaleLowerCase` / `Date` / `Math.random`。
- **G-6** Unicode 表随运行时变化；Node 大版本升级必须重跑 golden，变更需写明原因。

### R1 文本规范化

1. `NFKC` 归一，再做 `NFC`。
2. 换行统一：`\r\n` / `\r` → `\n`。
3. 删除 `U+200B–200F`、`U+202A–202E`、`U+2060`、`U+FEFF`。
4. 连续 ≥3 换行折叠为 2。
5. 规范化文本即**统计文本**；`chars` 记其 code point 数；证据片段也从此文本截取。
6. 不做：全文大小写折叠、删标点、拼写纠正、繁简转换。

### R2 页码与页眉行剔除

1. 删除独立成行且匹配 `^\s*(?:[-–—]\s*)?\d{1,4}(?:\s*[-–—])?\s*$` 的行。
2. 删除全文出现 ≥3 次、长度 ≤60 的完全相同的行；若该行命中 R5 章节关键词则保留。

### R3 参考文献截断

**L1 标题行**：trim 后匹配
`^(?:\d+[.、]\s*)?(references|bibliography|literature cited|works cited|参考文献|引用文献|參考文獻)\s*[:：.]?$`
且起始偏移 ≥ `max(全文 25%, 3000 code points)`、trim 长度 ≤ 60 → 从行首截断。

**L2 编号段落**（无标题时）：从 30% 处向后找连续 ≥8 行匹配 `^\s*(?:\[\d{1,3}\]|\d{1,3}[.、])\s+\S` 且平均行长度 ≤ 200 → 从该段首行截断。

**L3** 都不命中 → 不截断。

**反例保护**：标题行在 25% 之前 → 不截断，只记 `refHintEarly=true`。

**记录**：`refCut = {method:'L1'|'L2'|null, at, kept}`，只进日志与 golden。

### R4 统计上限

超过 400,000 code point → 取前 400,000（code point 边界切）；`chars` = 最终长度。

### R5 章节切分

标题行需同时满足：独立成行、trim ≤ 80 code point、不以句末标点结尾、含 ≥1 中文字符或全行 ASCII 字母 ≥3、命中关键词表（允许编号前缀）。

| 章节键 | 关键词 |
|---|---|
| `abstract` | abstract, 摘要, 内容提要 |
| `intro` | introduction, 引言, 前言 |
| `related` | related work(s), background, 相关工作, 文献综述, 研究现状 |
| `method` | method(s), approach, methodology, proposed method, 方法, 模型, 架构, 算法设计 |
| `experiment` | experiment(s), evaluation, results, 实验, 结果, 实验设置, 结果与分析 |
| `discussion` | discussion, 讨论 |
| `conclusion` | conclusion(s), 结论, 总结, 结语 |

归属最近的上一级标题；首个标题之前归 `other`（命中 abstract 标题则归 `abstract`）；二级标题沿用一级映射；未列入表的标题不构成边界。

### R6 别名匹配

**6.1 词典构建期校验**：区分大小写条目按 NFKC 原形去重、否则按 NFKC+lower 去重；同一别名出现在两条算法下 → **构建失败**。中文别名互为真子串（`注意力` ⊂ `自注意力`）→ 输出 warning 清单，人工确认。

**6.2 排序**：候选按 `(start 升序, end 降序, algorithmId 升序, alias 升序)`；禁用对象键序与集合插入序。

**6.3 左端点优先 + 同起点最长 + 消费**：取未消费区间内 start 最小者，同 start 取最长，消费 `[start,end)` 后继续。

**6.4 ASCII 边界**：候选两侧不得为 `[A-Za-z0-9_]`；`-` 视为边界，别名自身含 `-` 则按字面匹配。

**6.5 大小写（条目级）**：条目内任一别名满足 `^[A-Z0-9]{2,6}$` 且含字母 → 全条目原形精确比较；否则折叠比较。

**6.6 单复数**（仅 ASCII、非大小写敏感、长度 ≥3、不含数字）：`y`→`ies`；`s/x/z/ch/sh`→`es`；其余 +`s`；例外表见附表 B；**不支持反向**。

**6.7 中文边界**：不加任何边界断言；歧义裸词不进别名，靠词典治理。

**6.8 实现与性能**：允许 Aho–Corasick 或合并正则，但必须满足 6.2/6.3 顺序；40 万 code point × 300 别名单次 ≤300ms（冷机、单核）。实测不达标时改指标或改实现，不得改语义。

### R7 证据片段

≤3 条 / 每条 ≤200 code point；窗口为命中点前 60 后 140，向外扩到边界字符不切断词；不越过 R3 截断点；取自 R1 文本；三条尽量分属不同章节，同章节内起点相隔 ≥500；输出为纯文本（客户端转义）。

### R8 深度、告警与版本

**8.1** `chars < 120` → 拒绝（`VALIDATION`）。depth 由来源决定：arXiv HTML / ar5iv / PDF → `fulltext`；仅摘要 → `abstract`；粘贴默认 `fulltext`。告警（只进日志、工具返回的 `warnings[]` 与卡片）：fulltext 且 `chars < 3000` → `suspect:'short'`；PDF 且 `chars < 1200` → `suspect:'extract'`。

**8.2** 词典文件自带 `dictVersion`（`YYYY.MM.N`）；每条提及写入。正文已留存，词典升级后**原地重算**。重算结果必须与「直接登记」逐字节一致（G13）。

### R9 聚合与排序

提及 = `(paperId, algorithmId)`：`count`、`sections`（8 键）、`snippets`、`role=null`、`dictVersion`、`updatedAt`。排行默认：论文数 desc → 提及数 desc → 规范名 asc（码位比较）。覆盖率分母跟随筛选。缺年份计入论文数，不参与首见 / 最近年份与趋势（图例注明「另有 N 篇无年份未计入」）。

### R10 示例数据

`isSample=true` 默认不进入排行、统计栏、趋势、覆盖率；可开关；一键清除只删示例；可转正式（二次确认）。

### R11 正文留存

1. **存**规范化正文；**不存** PDF、上传文件、HTML 原文。
2. 存 **R1 之后、R3/R4 之前**的文本（规则演进时可原地重算，不必重抓）。
3. 正文记录：`paperId` / `textGz` / `rawChars` / `sha1` / `ingestVersion` / `storedAt`；论文侧记 `hasText` / `rawChars` / `textHash`。
4. 单篇压缩前 ≤ 5,000,000 code point，超出拒绝；库 > 2GB 时设置页提示。
5. 删除论文同事务删正文；撤销删除必须能恢复正文。
6. 导出默认 `includeText=0`；`includeText=1` 时提示「含论文全文，请勿外传」。
7. **不提供逐篇正文查看**；正文唯一出口是 `includeText=1` 全量导出。

### R12 工具输出与上下文预算（本版新增）

1. 工具返回 JSON **键序固定**（按 `outputSchema` 声明序）；集合一律数组；不出现 `undefined`。
2. 单次工具返回 **≤ 12,000 字符**；超限按 `truncated:true` + `shown/total` 截断，**不静默丢弃**。
3. **正文永不进入工具返回**。唯一例外：`textReadEnabled=true` 且用户当次明确要求，且返回 ≤ 8,000 字符 + 显式 `textRedacted` 之外的 `textIncluded:true` 标记。
4. 证据片段 ≤ 3 × 200 code point（继承 R7）。
5. 计数与统计一律返回数字，不返回已经渲染好的文案——文案由卡片 / 面板决定。

## 9. 数据模型

### 9.1 存储布局

```
<插件数据目录>/
  radar.json                # 结构快照（论文 / 提及 / 设置 / 撤销墓碑）
  radar.json.bak            # 上一次成功快照
  texts/
    p_<16hex>.txt.gz        # R1 规范化正文，gzip
  backups/
    radar-<yyyyMMdd>.json   # W2.0
```

**写入协议**：写 `radar.json.tmp` → `fsync` → `rename` 覆盖 → 保留 `radar.json.bak`。任何时刻磁盘上至少有一份完整快照。

**为什么不用 SQLite**：单用户、≤2000 篇、写频率低（一天几次）；快照 + 正文分片足够，且**不引入原生依赖**——这对一个要跨宿主版本发布的插件是硬收益。代价：每次写全量重写快照（2000 篇约 2–3MB，可接受）；超过 2 万篇需换存储（不在本期）。

### 9.2 papers

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | `p_<16hex>`，随机，避免补元数据后漂移 |

| venue | string(≤120) | 会议 / 期刊 |
| doi | string | 规范化（小写、去 `https://doi.org/` 前缀） |
| arxivId | string | 可空 |
| sourceUrl | string | 可空 |
| fields | string[] | 领域多标签，≤8，空则「未分类」 |
| depth | `fulltext` \| `abstract` | 统计依据 |
| chars | number | 参与统计的 code point 数 |

## 10. 接口需求

### 10.1 工具契约

**通用约定**

- 命名空间 `radar_`；读 / 写分组常量对外导出。
- 入参为宿主 schema 子集：`{ type, required?, enum?, items?, description }`；一律声明 `outputSchema`。
- 成功返回结构化对象，失败返回 `{ ok:false, error:{ code, message, field?, details? } }`；**不回显堆栈与正文**。
- 列表统一 `limit`（默认 20，上限 50）/ `offset`，返回 `{ items, total, truncated }`。
- 时间一律毫秒时间戳。
- 破坏性与批量操作**默认 `dryRun:true`**，必须显式 `false`。

### 10.3 错误码

| code | 触发 | 模型可见文案要点 |
|---|---|---|
| `VALIDATION` | 字段缺失/越界、正文 <120 字符、DOI 形态非法、内网地址 | 指出哪个字段、允许范围 |
| `NOT_FOUND` | 论文 / 算法 / undoToken 不存在或过期 | 区分「不存在」与「已过期」 |
| `CONFLICT` | overwrite 导入未确认、并发登记 | 给出可执行的下一步 |
| `CAPABILITY_OFF` | `writeEnabled=false` 时调用写工具（防御，正常不可达） | 说明如何开启 |
| `APPROVAL_UNAVAILABLE` | 需要审批但宿主无审批通道 | 说明原因，不重试 |
| `PAYLOAD_TOO_LARGE` | 正文 >5,000,000 code point、PDF >20MB | 给上限与当前值 |
| `UNSUPPORTED_MEDIA` | 非 PDF 附件 | 说明接受什么 |
| `EXTRACT_FAILED` | PDF 无可提取文字层 | 建议换版本或粘贴正文 |
| `UPSTREAM_FAILED` | 检索源全失败、arXiv 抓取失败 | 列失败源，其余源结果照常返回 |
| `ENGINE_MISMATCH` | `engines.dsh` 不满足 | 说明需要哪个宿主版本 |
| `INTERNAL` | 兜底 | 只说「内部错误」，细节进日志 |

## 13. 依赖与约束

### 13.1 插件形态约束（替代 web §13.1）

1. **不自建 HTTP 服务、不监听端口、不自建前端路由、不自建鉴权**。任何「打开一个页面」的需求都不成立。
2. **客户端只能通过 `ctx.slots` 往宿主已开放的槽位注册**（独立视图用 `conversation.view`），且只可注入 manifest `dsh.client.inject` 白名单里的客户端包；不直接操作宿主 DOM，不自造挂载点。
3. **颜色全部来自宿主 token**（`--dsw-alias-*` / `--dsw-radius-*` / `--ds-ease-in-out`）；禁止颜色字面量与自建主题。
4. **加载即空转**：加载插件不得探测、不起定时器、不发网络、不写盘。
5. **工具是纯 JSON 进 / 出**，禁止把正文塞进上下文（R12）；工具失败不抛栈。
6. **出站白名单 + 限速**：仅 §10.4 列出的域名；arXiv 抓取串行、间隔 ≥ 3 秒；批量并发 ≤ 2；OpenAlex 用带联系邮箱的 polite 方式。
7. **写操作必须有能力开关 + 审批**；开关关闭时工具不注册。
8. **配置项 schema 声明式**，提交即生效，不需要重启。
9. **所有注册项持有 disposer**，卸载后不留监听。
10. **第三方依赖最小化且不得含原生模块**；PDF 解析放子进程。
11. **宿主版本绑定**：`engines.dsh` 与 `engines.node` 必须声明并在激活时校验。
12. **不跨插件强耦合**：不复用其它插件的工具/服务作为主路径（这正是 P-7 放弃 v0.2 做法的原因）。
13. **抽取引擎零网络、零数据库、零配置依赖**，可独立测试。
14. **正文不出本机、不进上下文、不进浏览器渲染**。

### 13.2 外部站点约束

1. **全文抓取必须在宿主进程侧进行**（无浏览器，无 CORS 概念）。
2. arXiv 抓取串行、间隔 ≥ 3 秒；批量登记并发 ≤ 2。
3. 非 arXiv 全文无法自动获取：只能摘要级，或由用户提供 PDF / 粘贴正文。
4. 中文检索覆盖有限：OpenAlex 对中文期刊覆盖不全，面板要说明。

### 13.3 存储与备份

1. 正文压缩后入库；单篇压缩前上限 5,000,000 code point。
2. 估算：2000 篇 × 平均 3 万字符中文 ≈ 压缩前 180MB / gzip 后 50–70MB；快照本身约 2–3MB。
3. 每日备份（W2.0）保留 ≥7 份 → 约 0.5GB 量级；设置页显示体积，>2GB 时提示。
4. 备份文件含正文，只落本机磁盘，不进任何同步盘。

## 15. 风险与对策

| 风险 | 影响 | 对策 |
