## 1. 问题：报告答错了题

| 用户真实问题 | 现有报告 | 差距 |
|---|---|---|
| 这个领域**什么算法在用** | `decide` 答"你缺什么" | 答非所问 |
| 它们**怎么搭在一起** | 无 | 缺能力 |
| 我**下一步读什么** | `decide` 的 G1–G5 | 规则太窄，且是防守型 |

用户要的是**领域内的方法地图**，不是缺口体检。

## 2. 定义：领域洞察报告（insight）

> 一份**限定在单一领域**内、从客观统计出发、回答"这个领域里什么算法在用、它们如何搭配"的 Markdown 文档。

**回答三个问题**

1. 这个领域的**算法热度**排行（领域内，不是全库）
2. **算法组合**：哪些算法常在同篇出现，强度多少
3. 组合的**证据**：哪些论文、原文片段往哪儿看

**不回答**

| 不回答 | 原因 |
|---|---|
| 全局/业界"当前最火" | 库只反映**你读过的**，不是领域全局 |
| 组合的**具体结合方式**（串行/并联/集成） | 共现 ≠ 结合；需读原文 |
| 该读哪一篇 | 需外部检索，P2 |
| 哪个方法更先进 | 无质量信号，不可判 |

**一条铁律（写进报告正文）**

> 共现（co-occurrence）只说明两个算法**在同一篇论文中出现过**，不说明它们如何结合。判断结合方式必须读原文。

## 3. 报告骨架（5 节）

### 3.1 第 1 节 领域画像

| 指标 | 值 | 来源 |
|---|---|---|
| 领域 | 空气质量预测 | 参数 |
| 论文数 | 41 篇 | `radar_fields` |
| 占全库比例 | 55.4%（分母=74） | fields |
| 时间跨度 | 2020–2026 | `radar_trends`（该领域） |
| 摘要级占比 | N/41 | `radar_papers(depth=abstract, field)` |
| 算法种数 | K | ranking(field) 的 total |

**门槛**：领域 < 5 篇 → 只输出本节 + 第 5 节（局限），不出 Top 与组合。

### 3.2 第 2 节 算法热度 Top 10（领域内）

6 列：`| # | 算法（类型·分类）| 论文数 | 提及数 | 领域内覆盖率 | 首见年 |`

- 来源：`radar_matrix(field=…)` 取该领域的 cells + `radar_ranking(field=…)` 补齐类型/提及/年份（依赖 BUG-1 修复）。
- 分母 = **该领域论文数**（不是全库）。
- 表下必须写：`> 分母 = 该领域 N 篇；全库分母为 M 篇，两者不可混比。`
- 与全库排行的**差异**单独一行：`该领域 LSTM 领先 CNN，与全库顺序相反`（仅当 Top1 不同）。

### 3.3 第 3 节 算法组合 Top 10

5 列：`| # | 组合 | 同现篇数 | lift | 同现率 |`

- 来源：`radar_cooccurrence(field=…, minPapers=3)`。
- 排序：同现篇数 desc → lift desc。
- 过滤：同现 < 3 篇的组合不列（偶然同现）。
- 表下：`> lift > 1 表示比随机更常同篇出现；不等价于"搭配使用"。`
- 附一句**解读边界**：`同现率高但篇数少 → 可能是惯例搭配（如带基线对比）；篇数与 lift 都高 → 更可能是真实组合范式。`

### 3.4 第 4 节 组合证据（定位，不下结论）

每个 Top 3 组合一个小节：

```
### CNN + LSTM（15 篇 / lift 1.54）
同现论文（3 篇）：
- 〈标题〉（2024）· CNN 片段：「…」 · LSTM 片段：「…」
- …
> 两条片段不保证相邻，仅用于定位；是否串联请读原文。
```

- 片段只读已存 `snippets`，每算法 1 条、≤200 字符（R13-5）。
- **不渲染正文**。
- 论文选择：同现论文里按 `hitCount` desc 取 3 篇。

### 3.5 第 5 节 口径与局限

复用 review 第 9 章同源表，追加三条固定项：

| 项目 | 说明 |
|---|---|
| 样本量 | 「本领域 N 篇；<20 篇时排行不具统计意义」 |
| 库内偏差 | 「只反映已登记论文，不代表领域全局现状」 |
| 共现语义 | 「共现 ≠ 结合；无质量信号」 |

## 4. 口径规则（RI）

| # | 规则 |
|---|---|
| RI-1 | `mode=insight` **必须**给 `field`；缺 `field` → `VALIDATION`；`scope` 固定为 field |
| RI-2 | 热度分母 = 该领域论文数；全库数字不得混入 |
| RI-3 | 组合最小同现 **3 篇**，低于不列 |
| RI-4 | 共现不等于结合：第 3/4 节各有一条固定声明 |
| RI-5 | 片段只读已存 `snippets`，不重抽；不渲染正文 |
| RI-6 | 领域 < 5 篇降级：只出画像 + 局限 |
| RI-7 | 与 `radar_matrix` / `radar_cooccurrence` **同源一致**：同一领域同一算法篇数必须相等 |
| RI-8 | 可复现：同库同参数同 `generatedAt` → 内容一致 |

## 5. BUG-1：`radar_ranking` 的 `field` 参数失效

**现象**
- `radar_ranking(field:"空气质量预测")` 与 `field:"命名实体识别"` 输出**完全相同**；
- 覆盖率分母恒为 74（全库），而非领域篇数；
- 代码事实：`buildRankingTool.execute` 从未读取 `args.field`（`lib/index.js:1153-1206`），而工具 schema 里声明了它。

**影响**
- FR-3.8「排行可按领域筛选」未实现；
- `review` 的 `scope=field` 分支依赖它 → 报告里的领域排行也是错的；
- 模型若据此回答"某领域最火的算法"，会给出全库排名，**结论错误且不易察觉**。

**修复要求**
1. `field` 过滤生效：按 `paper.fields` 过滤，再聚合算法计数；
2. 覆盖率分母 = 领域论文数；
3. `firstYear` / `lastYear` 也要在领域内重算（否则年份区间错）；
4. 与 `radar_matrix` 的 cells 计数**逐项一致**（交叉校验）；
5. 保留 `q` / `type` 过滤与 `denominator` 语义。

**验收**：见 E35。

## 7. 用户故事增量

#### US-38 看一个领域的方法地图（W2.1 / P0）
**作为**读者，**我想**知道「空气质量预测」里哪些算法最常用，**以便**判断这个方向的主流方法。

- Given `mode=insight, field=空气质量预测`，Then 第 2 节给出领域内 Top10，分母是 41 而非 74
- Given 领域排行与全库排行 Top1 不同，Then 报告显式指出差异
- Given 领域只有 3 篇，Then 只出画像 + 局限，不出排行

#### US-39 看算法组合（W2.1 / P1）
**作为**读者，**我想**知道哪些算法常一起出现，**以便**找到值得读的组合范式。

- Given 组合表，Then 每行有同现篇数、lift、同现率；<3 篇的组合不出现
- Given 表下，Then 有一句「共现 ≠ 如何结合」
- Given 点看某个组合，Then 能看到 3 篇同现论文与各自片段，用于定位原文

## 9. 低保真原型

生成面板的用途选择从两项变三项：

```
用途  ( ) 汇报  ( ) 决策  (•) 领域洞察
范围  领域 [ 空气质量预测 ▾ ]     ← insight 时必须选，切到该项后自动必填
```

结果卡片不变（路径 + 字节 + 章节数），章节数显示为 5。

## 10. 风险与开放问题
