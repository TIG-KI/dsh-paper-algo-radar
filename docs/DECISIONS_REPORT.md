## P-10 · 润色层由谁执行

**结论：A —— 插件不持有模型句柄，只生成"待补写占位块"，由会话里的模型补写。**

### 理由

1. **不绑定模型**：插件一旦内调模型，就要选 provider、带密钥、处理超时——与插件定位（P-1）冲突。
2. **加载零副作用**（FR-10.5）：内调模型意味着存在隐式的网络路径，破坏「加载期不探测、不发网络」。
3. **可复现**：模型写的东西天然不可复现；放在插件外，`narrative=0` 的逐字节一致才成立（E26）。
4. **上下文边界**（P-6）：模型补写时只拿该章的**结构化 JSON**，不拿正文；这条比塞在插件里更好审计。

### 影响面

| 面 | 影响 |
|---|---|
| `radar_report` 参数 | `narrative` 语义从「生成解读」改为「生成占位块」 |
| 文件写入次数 | 开润色时报告会经历两次写（生成 → 模型补写）；文件名不变 |
| 可复现验收 | E26 只在 `narrative=0` 断言 sha256（现文已如此，无需改） |
| 报告头 | 含模型生成内容时必须标 `> 本报告含模型生成段落（P-10）` |

### 实施约束（给开发）

1. `narrative=1` 时，在每章末尾插入：

   ```
   <!-- radar:insight section=<N> -->
   > _（此处待补写解读）_
   ```

   并附带一个 **chapter payload**（该章已渲染数据的结构化副本）供模型使用。
2. 插件**不调用任何模型**，不读取 API key，不发起网络请求。
3. 模型补写后，调用方须在报告头加标注；不得改动事实区任何数字。
4. 若无人补写，占位块原样保留，报告仍是有效产物（只是多几行空块）。

### 被否决

| 方案 | 否决理由 |
|---|---|
| B · 插件内调模型 | 需模型句柄与密钥；违反 P-1 / FR-10.5；不可复现；审计面变大 |

## P-11 · 报告落点与命名

**结论：落在 `exports/reports/`，文件名自带 mode / scope / 时间戳，同名追加序号、不覆盖。**

### 规则

| 项 | 规则 |
|---|---|
| 目录 | `<数据目录>/exports/reports/`（与现有 `exports/` 同级子树，便于一起备份） |
| 文件名 | `radar-report-<mode>-<scopeSlug>-<YYYYMMDD-HHmm>.md` |
| `mode` | `review` / `decide` |
| `scopeSlug` | `all` / `field-<slug>` / `year-<from>-<to>` |
| 时间戳 | 本地时间（与报告头一致），分钟精度 |
| 同名 | 追加 `-2`、`-3`…，**绝不覆盖** |
| `path` 参数 | 只能指定**目录**，且必须在工作区内；越界拒绝（`VALIDATION`） |
| 权限 | 目录不存在则创建；创建失败 → 人类可读原因 |

### 理由

1. **不覆盖**：报告是"当时的证据"，覆盖等于销毁历史。研究场景尤其不能丢。
2. **不走 `docs/`**：`docs/` 是需求文档区，混入生成物后不好清理、也不好进版本库。
3. **同级子树**：与 `exports/` 一起备份/迁移，路径语义一致。
4. **文件名可排序**：时间戳在尾部，`ls` 天然按时序；scope 在中段，便于同范围比对。

### 被否决

| 方案 | 否决理由 |
|---|---|
| 与 `exports/` 平级混放 | JSON/CSV 与报告混在一起，清理与备份策略不同 |
| 按日期建子目录 `reports/2026-10-23/` | 目录层级变深，个人规模下收益不足 |
| 固定文件名覆盖 | 丢历史报告，与研究用途冲突 |

### 影响面

| 面 | 影响 |
|---|---|
| FR-13.1 入参 | 增加 `path?`（目录），其余不变 |
| 备份 | 报告随 `exports/` 进入备份范围；**报告体积小**（KB 级），可接受 |
| 可移植 | 报告不进 `store.json`，导入导出不涉及 |
