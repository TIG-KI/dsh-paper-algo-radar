## 1. 角色

只有一个真人用户——维护自己阅读轨迹的研究者。他在不同时刻戴不同的帽子：

| 帽子 | 出现场景 | 关心什么 |
|---|---|---|
| **读者**（主要） | 读到一篇论文的当下 | 用最少的动作把这篇记下来，别打断阅读 |
| **回顾者** | 月末、开题前 | 我到底在读什么？哪些模型反复出现？ |
| **汇报者** | 组会、写开题报告 | 能不能导出一份能直接贴的材料 |
| **治理者** | 发现漏计、词典过时 | 数字为什么是这样，怎么改对 |
| **迁移者** | 换电脑、重装 | 数据能不能带走、能不能回来 |

**不是用户的人**：团队成员、被分享者、机构管理员——本期明确不存在（PRD §2.2）。

## 2. 故事地图（一条真实旅程）

```
发现方向 ──▶ 找论文 ──▶ 登记 ──▶ 立刻看到回执 ──▶ 回看排行
   │                        │                        │
   └─ 领域检索 ────────────┤                        ├─▶ 下钻看证据
                            └─ 链接 / PDF / 正文      ├─▶ 年份与领域
                                                     └─▶ 导出汇报
词典过时 ──▶ 重算 ──▶ 数字更新        换电脑 ──▶ 导出 ──▶ 导入
```

三个**高频**动作：说一句话登记、打开面板看排行、下钻看某算法出现在哪。
四个**低频但致命**动作：重算、导出、导入、撤销删除。

## 3. 用户故事

> 格式：角色 / 想要 / 为了 ｜ 验收用 Given-When-Then。
> 优先级沿用 PRD：**P0** 阻塞 W0 或 W1.0；**P1** W1.1；**P2** W1.2 / W2.0。

### E1 · 登记：把"读到一篇"的成本压到一次动作

#### US-01 一句话登记（W0 / P0）
**作为**读者，**我想**在会话里说「把 arXiv 2006.11239 加进雷达」，**以便**不离开对话就完成登记。

- Given 我给出 DOI / arXiv id / arXiv 链接，When 请求登记，Then 返回回执：标题、命中算法与次数、`depth`、字符数、`warnings[]`
- Given 回执，Then **卡片 ≤ 6 行、不含任何正文**，我据此就能判断"这篇值不值得读"
- Given 全文抓取失败，Then 降级为摘要级登记并在回执标注，不阻断
- Given 解析或抽取失败，Then 整篇不入库、错误码明确，库内不留半条记录

> 关联：FR-1.11 / FR-1.7 / FR-1.12 / FR-9.8 / FR-6.6
> 验收：E2、E19

#### US-02 面板里粘贴链接（W0 / P0）
**作为**读者，**我想**在雷达面板里粘一个链接就登记，**以便**不切回会话也能录。

- Given 面板输入框，When 粘贴 DOI / arXiv 链接并提交，Then ≤ 3 次点击、≤ 15 秒内出命中结果
- Given 输入是普通网页链接，Then 明确告诉我「需要 DOI / arXiv id 或正文」，不猜

> 关联：FR-1.7 / §2.1 单篇登记耗时

#### US-03 粘贴正文登记（W0 / P0）
**作为**读者，**我想**把摘要或正文粘进去就能统计，**以便**处理没有 DOI 的中文文献。

- Given 正文 ≥ 300 字符，When 提交，Then 完成抽取并返回回执
- Given 正文 < 300 字符且我给的是摘要，Then 按摘要级（≥ 120 字符）处理并标注，而不是直接拒绝
- Given 参考文献段落，Then 其中的算法名**不计入**统计

> 关联：FR-1.1 / FR-1.3 / FR-1.4 / §8 R1–R4
> 验收：A1、A2、A2b、A3

#### US-04 上传 PDF（W1.1 / P1）
**作为**读者，**我想**直接把 PDF 丢给它，**以便**不用先转成文本。

- Given 含文字层的 PDF（含中文期刊常见的 CID/Type0 字体），Then 提取成功并登记
- Given 扫描件，Then `EXTRACT_FAILED` + 人话说明「这是图片，需要文字层」，**不报堆栈**
- Given 任何情况，Then 落盘目录里**没有 PDF 残留**，只有 gzip 正文

> 关联：FR-1.8 / FR-10.8 / FR-7.7
> 验收：E3、E9

#### US-05 同一篇不会变两篇（W0 / P0）
**作为**读者，**我想**先登记无年份、之后再补年份，**以便**不用先查元数据。

- Given 已登记「标题 + 正文（无年份）」，When 我用 DOI 再登记一次，Then 库内仍是一篇，字段被补齐
- Given 同一篇从 DOI 口和 arXiv 口分别进来，Then 仍是一篇（三键任一命中即同一篇）

> 关联：FR-1.2 / FR-1.5
> 验收：E10（已实测通过）、E16

#### US-06 摘要级也要可见（W0 / P0）
**作为**回顾者，**我想**看出哪些论文只有摘要，**以便**知道我看到的排行有多少是"低质量输入"。

- Given 库里有摘要级论文，When 看统计串，Then 显示「其中 N 篇仅摘要」
- Given 看排行，Then 摘要级论文正常计入但可被筛选出来

> 关联：FR-1.4 / FR-3.8 / FR-9.7

### E2 · 找论文：从"想进一个方向"到"批量入库"

#### US-07 领域检索（W0 / P0）
**作为**读者，**我想**说「搜一下空气质量预测」，**以便**快速看到这个方向的代表作。

- Given 关键词，Then 返回候选：标题 / 年份 / 会议 / 引用数 / 来源 / 是否已有摘要
- Given 某源超时或挂掉，Then 其余源照常返回，并**如实标出哪几个源失败**
- Given 我想要更精确，Then 可按源、年份区间、最低引用数过滤

> 关联：FR-6.1 / 6.2 / 6.3 / 6.8
> 验收：B1（中文关键词要能出结果）

#### US-08 批量登记（W1.0 / P0）
**作为**读者，**我想**勾几篇一次登记，**以便**一次搞定一个方向。

- Given 候选列表，Then 默认全选、可逐条取消，按钮显示「登记选中的 N 篇」
- Given 开始登记，Then 逐条回报状态（算法数 + 全文/仅摘要），**单条失败只在该行显示原因**
- Given 中途想停，Then 可取消；已完成条目正常入库，界面标注「已取消，N 条已完成」

> 关联：FR-6.4 / 6.5 / 6.10
> 验收：B2、B3、E18

#### US-09 已在库的不重复登记（W1.1 / P1）
**作为**读者，**我想**看候选时就标出「已登记」，**以便**不白跑一次抓取。

- Given 候选已在库（三键任一命中），Then 标「已登记」且默认不勾选

> 关联：FR-6.9

#### US-10 拿不到全文也要能降级（W1.0 / P0）
**作为**读者，**我想**知道这篇为什么只有摘要，**以便**决定要不要自己去找 PDF。

- Given 非 arXiv 且无摘要，Then 明确标「无摘要 / 全文，登记会失败」
- Given arXiv 抓取失败，Then 区分原因：没有 HTML 版 / 超时 / 被挡，而不是笼统说"失败"

> 关联：FR-6.6 / 6.7

### E3 · 看数字：排行是产品的脸

#### US-11 打开就看到排行（W0 / P0）
**作为**回顾者，**我想**一打开面板就看到「我读的论文里哪些算法出现最多」，**以便**三分钟内拿到第一份价值。

- Given 库里有数据，Then 首屏是排行表：排名、规范名、分类、类型、论文数、提及数、覆盖率条、年份区间
- Given 我只看"涉及多少篇"，Then 默认按**论文数**排序，不被长文里刷屏的提及数带偏
- Given 我想看总量，Then 可切「提及数」

> 关联：FR-3.0 / 3.1 / §2.1 首次价值时间
> 验收：E1（空态走查）

#### US-12 切换统计口径（W0 / P0）
**作为**治理者，**我想**在"论文数"和"提及数"之间切换，**以便**区分"读得广"和"这篇反复提"。

- Given 切到提及数，Then 排序变化，且每行仍同时显示两个数字，我知道自己在看哪个口径

> 关联：FR-3.0

#### US-13 筛掉噪音（W1.1 / P1）
**作为**回顾者，**我想**按类型、关键词、领域、年份、深度、是否旧口径过滤，**以便**只看我这个月的方向。

- Given 应用筛选，Then 排行与覆盖率**分母同步变化**，且分母数字显示出来

> 关联：FR-3.2 / 3.3 / 3.4 / 3.8

#### US-14 覆盖率要说得清（W1.1 / P1）
**作为**治理者，**我想**看到"这个算法出现在我读过的 40% 论文里"，**以便**判断它是不是我的主力方法。

- Given 覆盖率条，Then 百分比与分母都可见，分母口径跟随当前筛选

> 关联：FR-3.4

#### US-15 下钻到证据（W1.0 / P0）
**作为**读者，**我想**点一个算法就看到「哪几篇用了它、原文怎么说」，**以便**确认统计不是幻觉。

- Given 点击排行行，Then 进入详情：论文清单（含次数）、证据片段、章节分布、年份分布
- Given 证据片段，Then 每条 ≤ 200 字符，且**是原文摘录**而不是模型转述

> 关联：FR-3.5 / FR-2.4 / FR-2.5 / §6 S-c
> 验收：E4

#### US-16 追问用法（W0 / P0）
**作为**读者，**我想**问「这几篇里 Transformer 是怎么用的」，**以便**让模型基于结构化命中回答，而不是凭印象。

- Given 我的问题，Then 模型拿到命中论文 + 片段 + 章节分布，回答**引用片段**
- Given 库里没有，Then 明确说没有，不编

> 关联：FR-2.4 / 2.5 / §3 S8

### E4 · 时间与领域

#### US-17 看时间跨度（W1.1 / P1）
**作为**回顾者，**我想**知道「我什么时候开始关注扩散模型的」，**以便**复盘自己的转向。

- Given 算法行，Then 显示首见年与最近年；无年份论文不参与并说明
- Given 趋势图，Then 同时提供**表格视图**（图表不是唯一入口）

> 关联：FR-4.1 / 4.2 / 4.3 / FR-9.4
> 验收：D1（Top10 人工抽查）

#### US-18 看领域分布（W1.1 / P1）
**作为**回顾者，**我想**看我在 NLP / 时序 / 图学习各领域的投入比例，**以便**知道自己是不是偏科。

- Given 领域分布，Then 横向条形（不是环图），数字可读
- Given 领域 × 算法矩阵，Then 能看出"某个领域的主打算法"

> 关联：FR-5.1–5.4

#### US-19 整理领域标签（W1.1 / P1）
**作为**治理者，**我想**把「NLP」和「自然语言处理」合并，**以便**分布不发散。

- Given 标签管理，Then 可重命名、可合并，合并后历史论文跟着走

> 关联：FR-5.5

### E5 · 数据可信与搬迁

#### US-20 词典升级后重算（W1.0 / P0）
**作为**治理者，**我想**新增一批算法名后把旧论文重算一遍，**以便**历史数字跟上新口径，而不是新旧混着看。

- Given 词典升级，Then 面板显示「待重算 N 篇」，并区分「有正文可算」与「无正文不能算」
- Given 我触发重算，Then **先给 diff 预览**（哪些篇、增删了什么），确认后才写库
- Given 重算完成，Then 全部提及的 `dictVersion` 等于当前版本；重算不联网

> 关联：FR-2.9 / 2.6 / §3 S7
> 验收：E11、E12

#### US-21 导出带走（W0 / P0）
**作为**迁移者，**我想**导出成文件，**以便**备份或换机。

- Given 导出，Then 落到工作区文件，**内容不进对话上下文**（我不会被一坨 JSON 淹没）
- Given 我选含正文，Then 文件明显变大，且提示「含论文全文，请勿外传」
- Given 排行 CSV，Then Excel 打开中文不乱码

> 关联：FR-7.3
> 验收：E6

#### US-22 导入回来（W1.0 / P0）
**作为**迁移者，**我想**把导出文件导回去，**以便**换机后继续用。

- Given 导入文件，Then 默认只给差异预览（新增/更新/冲突），确认后才写
- Given 合并模式，Then 同一篇按三键命中、保留本地 id，不产生重复
- Given v0.2 的 `store.json`，Then 自动识别并迁移（5 篇进来还是 5 篇）

> 关联：FR-7.4
> 验收：E16、E6

#### US-23 误删可撤销（W1.1 / P1）
**作为**读者，**我想**删错了能退回来，**以便**不用重录。

- Given 删除，Then 10 秒内可撤销，论文、提及、正文一起回来；超时给出明确失败
- Given 删除前，Then 走审批，且审批文案里不含正文

> 关联：FR-1.6 / FR-8.7
> 验收：E13、C1

#### US-24 清空但别手滑（W1.1 / P1）
**作为**迁移者，**我想**能清空全部数据，**以便**在换机前从零开始。

- Given 清空，Then 需输入确认词 + 审批；清空前提示先导出

> 关联：FR-7.5

#### US-25 自动备份（W2.0 / P2）
**作为**迁移者，**我想**每天自动留一份快照，**以便**忘记导出也不至于丢。

- Given 有写入或读状态，Then 当天最多备份一次，保留 ≥ 7 份，**不起定时器**

> 关联：FR-7.6

#### US-26 隐私边界可信（W1.0 / P0）
**作为**读者，**我想**确定正文不会跑进模型上下文、也不会留下 PDF，**以便**放心录别人论文的全文。

- Given 任何工具返回，Then 无正文（片段 ≤ 200 字符/条）
- Given 数据目录，Then 只有 `store.json` 与 `texts/*.txt.gz`，无 PDF、无明文副本
- Given 日志，Then 不含正文

> 关联：FR-7.7 / P-6
> 验收：E9、E21

### E6 · 上手与宿主礼仪

#### US-27 空库给我下一步（W1.1 / P1）
**作为**新用户，**我想**打开空白面板时知道能做什么，**以便**不愣在那里。

- Given 空库，Then 三个入口：搜领域 / 粘链接 / 载入示例
- Given 示例数据，Then 明确标记「示例」，默认不计入任何统计，可一键清除

> 关联：FR-11.1 / 11.2
> 验收：E1、E17

#### US-28 面板像宿主的一部分（W1.1 / P1）
**作为**用户，**我想**面板跟随宿主深浅色、在窄屏也能用、能用键盘操作，**以便**不觉得这是个外挂。

- Given 宿主切深色，Then 面板跟随且无硬编码色值
- Given 360px 宽，Then 排行变单列卡片，无横向滚动
- Given 键盘，Then 关键控件有焦点与文字标签，`Esc` 回到列表

> 关联：FR-9.1 / 9.3 / 9.5
> 验收：E22

### E7 · 权限：能关、能审、能拆

#### US-29 关掉写能力（W1.0 / P0）
**作为**用户，**我想**一键关掉所有写操作，**以便**只读地看数据，或避免模型误改。

- Given `writeEnabled=false`，Then 写工具**不注册**（不是运行时拒绝），面板写按钮置灰并说明原因

> 关联：FR-8.6 / 8.7
> 验收：E17

#### US-30 破坏性操作先问我（W1.0 / P0）
**作为**用户，**我想**删除、清空、覆盖导入前被问一次，**以便**不被自动化静默摧毁数据。

- Given 破坏性操作，Then 走宿主审批；`declined` 即停，不换路径重试

> 关联：FR-8.5 / 8.7
> 验收：E13

#### US-31 版本不匹配别硬上（W0 / P0）
**作为**用户，**我想**宿主版本不够时插件明确拒绝，**以便**不出现半加载的怪状态。

- Given `engines.dsh` 不满足，Then 拒绝激活 + 人话提示，工具不注册

> 关联：FR-10.2
> 验收：E8

#### US-32 卸载重装数据还在（W0 / P0）
**作为**迁移者，**我想**卸载插件不删数据，**以便**敢装敢卸。

- Given 卸载再重装，Then 数据目录保留、自动恢复，版本不同给提示

> 关联：FR-10.4 / 10.6
> 验收：E20

#### US-33 加载即静默（W0 / P0）
**作为**用户，**我想**装上插件后宿主不变慢、不乱发请求，**以便**信任第三方插件。

- Given 加载后立即检查，Then 零网络、零写盘、零定时器

> 关联：FR-10.5
> 验收：E21

## 4. 非用户故事：工程约束

下面这些**不是**用户价值，硬套"As a user"会造假。它们归"约束"，验收按技术断言做：

| 约束 | 对应 FR | 为什么不是故事 |
|---|---|---|
| 工具契约（schema 子集、`outputSchema`、分页、键序、≤12k 字符） | FR-8.2 / 8.3 / 8.4 / R12 | 用户感知不到，但会以"回答被截断"体现——已由 US-16 的"不编"覆盖 |
| 同一服务层、无第二套实现 | FR-8.1 / §6 规则 1 | 架构约束 |
| 原子写（tmp → fsync → rename） | FR-7.2 | 可靠性约束 |
| 读/写工具名单常量 | FR-8.2 | 测试与策略锚点 |
| 系统提示段（何时登记、禁止 shell 绕过） | FR-8.8 | 行为约束，不是功能 |
| 配置 `volatile` 热生效 | FR-10.7 | 体验细节 |
| i18n 骨架 | FR-9.6 | 预留 |
| 卡片渲染只回结构化结果、不二次请求 | §6 规则 2 | 架构约束 |

## 5. 反故事（明确不做，防止范围蔓延）
