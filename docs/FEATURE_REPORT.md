## 1. 问题：现在的导出是表格，不是报告

| | 现有 `radar_export`（FR-7.3） | 本需求 |
|---|---|---|
| 产出 | CSV / JSON，一行一条 | 有章节、有结论、有口径注释的文档 |
| 谁看 | 程序、备份工具 | 人（导师、未来的自己） |
| 回答 | "有哪些数字" | "我读出了什么、下一步读什么" |
| 可复现 | 天然 | **需要专门设计**（本需求主要成本） |

一句话价值：**从「我有一份排行」升级到「我能拿出说明自己研究状态的结论，并知道下一步补哪里」。**

## 2. 目标与非目标

**目标**：① 两份报告 `review` / `decide`；② 每个数字可回溯口径与来源；③ 事实与解读物理分区；④ 关闭润色时逐字节可复现。

**非目标**：不做引用体系（GB/T 7714 / BibTeX）；不把正文放进报告或送进模型（沿用 P-6）；不做 Word / HTML / PDF（P2）；不自动联网推荐具体论文；不做趋势预测。

## 3. 能力边界与归属（B1 修订）

| 项 | 结论 | 理由 |
|---|---|---|
| 工具分组 | 归 **read 组**（`RADAR_READ_TOOL_NAMES`） | 不写库、不改快照、不改 `texts/` |
| `writeEnabled=false` | **仍注册、仍可用** | 只读库 + 写工作区文件，不触碰写能力边界 |
| 落盘通道 | **复用 FR-7.3 的写盘封装**（`tmp → fsync → rename`） | 禁止第二套 IO |
| 命令面 | `/radar report` 纳入；同步修改 **FR-8.9** 文本 | 现 FR-8.9 只列 status/reextract/export，不改就自相矛盾 |
| 路径约束 | 只能写工作区内路径，拒绝工作区外与相对越界 | 与 `radar_export` 一致 |

## 4. 报告结构

### 4.1 `review` —— 给导师 / 组会（10 章）

| 章 | 内容 | 数据来源 |
|---|---|---|
| 1 摘要 | 3–5 条**数字陈述** | 统计串 |
| 2 数据画像 | 篇数、跨度、摘要级占比、领域数、`dictVersion`、陈旧、可重算 | state |
| 3 算法排行 Top 10 | 论文数 / 提及数双列 + 覆盖率 + 首见年 | ranking |
| 4 类型分布 | DL / ML / MATH 论文数与占比 | ranking 聚合 |
| 5 时间线 | 年度论文数 + 各算法首见 / 最近年 | trends |
| 6 领域分布 | 领域论文数（**表格**）；「未分类」单列 | fields |
| 7 代表性论文 | 每领域按**算法数降序**取前 2；摘要级加标记 | papers |
| 8 **最近 N 天新增**（新） | N 默认 30，可配；列出新增论文与其 Top 算法 | `readAt` + FR-4.2 |
| 9 可信度与局限 | 摘要级占比、小样本、旧口径、无正文 | derive |
| 10 附录 | 完整排行 + 论文清单 | 全量 |

### 4.2 `decide` —— 下一步读什么（5 章）

| 章 | 内容 |
|---|---|
| 1 缺口清单（结论先行） | 按 §5 规则；每条附严重度 |
| 2 缺口证据 | 数字 + 命中规则的原文 |
| 3 **方向与动作**（合并） | 每缺口 → 一个方向（领域/类型映射）+ 一个可执行动作 |
| 4 口径附录 | 同 review 第 9 章 |
| 5 未评估项 | 数据不足而不评估的领域/类型，显式列出 |

## 5. 缺口判定规则（确定性，可测）

| 缺口 | 触发条件 | 严重度 | 方向 / 动作 |
|---|---|---|---|
| G1 输入质量欠账 | 摘要级占比 > 50%，或 无正文篇数 > 0 | 高 | 方向：补全文；动作：列可补清单（按命中算法数降序） |
| G2 领域过薄 | **分级**：领域 = 1 篇 → **不评估**（进第 5 章）；= 2 篇 → 薄；≥ 3 篇 → 正常 | 中 | 方向：补该领域；动作：给出该领域现有论文作起点 |
| G3 类型失衡 | 库 ≥ 20 篇且某类型占比 < 10% | 中 | 方向：补该类型基础；动作：无（需外部检索） |
| G4 时间断层 | 库 ≥ 5 篇且最新论文年 < `referenceYear` − 2 | 中 | 方向：读新工作 |
| G5 口径陈旧 | `stalePapers > 0` | 低 | 动作：重算 N 篇 |

- 「未分类」**不计入 G2**，单独统计。
- 全部规则是**阈值 + 计数**，无模型判断；规则不命中时输出「未发现缺口」，不硬凑。

## 6. 口径与可复现规则（RD）

| # | 规则 |
|---|---|
| RD-1 | **只读**：生成前后不得修改库、`texts/`、配置 |
| RD-2 | **落盘**；工具返回只给路径、字节数、章节标题列表 |
| RD-3 | 报告内容**不进对话上下文** |
| RD-4 | 每个数字带口径标签：`论文数` / `提及数` / `分母=N` |
| RD-5 | 报告头必带：`generatedAt`、库规模、`dictVersion`、摘要级占比、陈旧篇数、可重算篇数、`referenceYear` |
| RD-6 | 证据片段 ≤3 条/算法、每条 ≤200 字符；**不得出现整段正文** |
| RD-7 | 事实区与解读区物理分开：解读以 `> AI 解读（可关闭）` 引用块出现，默认关闭 |
| RD-8 | 润色层只接收**结构化统计 JSON**，不接收正文；提示词禁止生成新数字 |
| RD-9 | 关闭润色时，同库同参数两次生成内容一致 |
| **RD-11** | 排序**必须复用 FR-3.0**：论文数 desc → 提及数 desc → 规范名 asc（码位比较） |
| **RD-12** | 片段**只读已存 `snippets`**，不得重新抽取（重抽依赖正文，会破坏只读与一致性） |
| **RD-13** | 时间参数化：`generatedAt`（默认当前，ISO-8601）、`referenceYear`（默认系统年）；两者写入报告头 |
| **RD-14** | 覆盖率分母**跟随 scope**（沿用 FR-3.4）：全库 / 领域 / 年份窗口 |
| RD-15 | 数据不足降级：< 5 篇只出数据画像 + 局限 + 未评估项，不出结论章 |

## 8. 用户故事增量

#### US-34 生成汇报报告（W2.1 / P0）
**作为**汇报者，**我想**一键生成能贴进组会材料的 Markdown，**以便**不用手抄数字。

- Given 库有 ≥5 篇，When 生成 `review`，Then 文件含 §4.1 的全部 10 章（不足 5 篇时见 US-36b）
- Given 生成完成，Then 返回只有路径与章节目录，**无正文内容**
- Given 打开文件，Then 每个排行数字旁有"论文数/提及数 + 分母"

#### US-35 生成决策报告（W2.1 / P1）
**作为**读者，**我想**一眼知道下一步该补什么，**以便**不在已有方向上重复读。

- Given 现有 5 篇、4 篇摘要级，When 生成 `decide`，Then 第 1 章命中 G1；**G2 命中 3 个领域**（时空预测 / 深度学习 / 空气质量预测，各 1 篇）→ 按分级进第 5 章「未评估」，**不报警**；G3/G4 不命中并写明理由
- Given 规则全不命中，Then 输出「未发现缺口」，不硬凑建议

#### US-35b 双入口（W2.1 / P0）
**作为**读者，**我想**在工具栏和口径页都能生成报告，**以便**不用记入口在哪。

- Given 主视图工具栏，Then 有「生成报告」按钮
- Given 口径页脚，Then 也有；两处点开是同一个面板、走同一服务方法

#### US-36 报告可信（W2.1 / P1）
**作为**治理者，**我想**确认数字不是我编的，**以便**敢拿它进材料。

- Given 报告头，Then 有 `dictVersion` / 摘要级占比 / 陈旧篇数 / 可重算篇数 / `referenceYear` / `generatedAt`
- Given 片段，Then ≤3 条/算法、每条 ≤200 字符、带标题与年份
- Given 开了润色，Then 解读段独立成块，且**其中每个数字都能在事实区找到**

#### US-37 同一份报告可复现（W2.1 / P1）
**作为**研究者，**我想**隔天再生成得到相同结论，**以便**引用自己之前的材料。

- Given 库与参数未变、`narrative=0`、`generatedAt` 固定，Then 两次生成的内容一致
- Given 开了润色，Then 报告标注「含模型生成段落，不保证逐字复现」

## 14. 排期建议（你已定：报告先做）

按你的决定，报告排在数据质量动作之前。**一个必须写进 W2.1 验收的附注**：在这 5 篇（4 篇摘要级）的库上，`review` 的排行会被单篇 43 次带偏，`decide` 第一句就是「4/5 是摘要级」。所以 E25 的期望里包含「报告如实呈现数据质量差」——**报告的第一份产出，就是证明自己的数据需要补**。这不是缺陷，是设计意图。
